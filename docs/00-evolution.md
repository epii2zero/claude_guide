# 채팅에서 에이전트까지 — Claude의 발전 과정

> 발표 Part 1의 근거 자료. 각 단계를 **"당시의 한계 → 그것을 푼 기능 → 지금의 사용법
> → 이때 필요해진 역량"** 구조로 정리한다. 모든 시기·명칭은 Anthropic 공식
> 발표(anthropic.com/news)와 공식 문서(Claude Code changelog)로 검증했다 (2026-08-30 기준).

## 단계별 상세: 한계 → 기능 → 사용법

### 1. 출발점 — 단순 채팅 (2023.03)

- **무엇**: 첫 Claude 모델 공개. API와 파트너용 채팅 인터페이스로 시작.
- **가치와 한계**: 질문-답변만으로도 유용했지만, ① 알고 있는 것은 학습 데이터뿐이고
  ② 결과를 받으려면 사람이 모든 맥락을 복사해 넣고 결과를 복사해 나와야 했다
  (복붙 워크플로우) ③ 환각 위험.
- **지금도 유효한 기본기**: 이때 확립된 프롬프트 요령 — 맥락 제공(코드·에러 로그·제약조건),
  역할·출력 형식 지정, 단계적 요청 — 은 에이전트 시대에도 그대로 통한다.
- **필요해진 역량 — 명확하게 묻기(프롬프트 작성)**: 맥락·의도·제약·원하는 형식을
  언어로 정리하는 능력. 이후 모든 시대의 바탕이 되는 기본기.
- 출처: [Introducing Claude](https://www.anthropic.com/news/introducing-claude)

### 2. 컨텍스트의 확장 — 긴 컨텍스트와 claude.ai (2023)

- **한계**: 초기 컨텍스트 창은 작아서 문서를 잘게 쪼개 넣어야 했다.
- **기능**: 100K 컨텍스트(2023.05, Claude 1.3) → Claude 2와 함께 누구나 쓰는
  claude.ai 공개(2023.07) → Claude 2.1에서 200K(2023.11). 이후 세대에서 1M까지 확대.
- **사용법**: 문서·로그 파일·코드 여러 개를 통째로 첨부하고 질문하기.
  "요약해줘"를 넘어 "이 로그에서 장애 원인 찾아줘"가 가능해진 지점.
- **함께 등장한 것 — 시스템 프롬프트** (Claude 2.1, 2023.11): 매 대화 반복하던 역할·규칙
  지시를 대화와 분리해 고정하는 API 기능. "반복하는 지시를 어딘가에 담아둔다"는
  발상의 출발점 — 이 줄기가 Projects → CLAUDE.md → Skills로 이어진다 (아래 "지시의 계보" 참고).
- **필요해진 역량 — 컨텍스트 큐레이션**: "많이 넣을 수 있다"와 "잘 넣는다"는 다르다.
  무엇을 주고 무엇을 뺄지, 어떤 순서로 보여줄지 선별하는 능력.
- 출처: [100K context windows](https://www.anthropic.com/news/100k-context-windows),
  [Claude 2](https://www.anthropic.com/news/claude-2),
  [Claude 2.1](https://www.anthropic.com/news/claude-2-1)

### 3. 눈이 생기다 — Claude 3와 비전 (2024.03)

- **한계**: 스크린샷·아키텍처 다이어그램·에러 화면을 텍스트로 옮겨 적어야 했다.
- **기능**: Claude 3 패밀리(Haiku/Sonnet/Opus)에서 이미지 입력 지원.
  용도별 모델 라인업(속도 vs 성능)도 이때 정착.
- **사용법**: 에러 스크린샷 그대로 붙여넣기, 다이어그램 보고 코드 생성,
  UI 시안 리뷰.
- **필요해진 역량 — 입력 형태 선택**: 말로 설명할지, 보여줄지 판단하기.
  10줄 설명보다 스크린샷 한 장이 나은 경우를 아는 감각.
- 출처: [Claude 3 family](https://www.anthropic.com/news/claude-3-family)

### 4. 손이 생기다 — Tool use (2024.05)

- **한계**: 모델이 학습 지식에 갇혀 있고, 계산·검색·조회는 못 했다.
- **기능**: Tool use(함수 호출) API 정식 출시. 개발자가 정의한 도구를 모델이
  스스로 골라 호출 — **에이전트로 가는 첫 단추**. 이후 웹 검색(2025.03),
  코드 실행 등 서버측 도구로 확장.
- **사용법**: (일반 사용자 관점) 웹 검색으로 최신 정보 질문, 분석 도구로
  CSV 업로드 후 계산·차트. (개발자 관점) API에서 자체 도구 연결.
- **필요해진 역량 — 능력 범위 파악**: 모델이 지금 무엇을 할 수 있고 없는지 알고
  요청을 거기에 맞추는 것. 개발자에게는 도구 인터페이스를 명확하게 설계하는 능력
  (좋은 도구 설명 = 좋은 API 문서).
- 출처: [Tool use GA](https://www.anthropic.com/news/tool-use-ga),
  [Web search](https://www.anthropic.com/news/web-search)

### 5. 산출물이 생기다 — Artifacts (2024.06)

- **한계**: 코드·문서를 만들어도 대화 로그 속에 묻혔다.
- **기능**: Claude 3.5 Sonnet과 함께 Artifacts 공개(06.20). 코드, 문서,
  동작하는 HTML 프로토타입이 대화 옆 별도 창에 "작업물"로 만들어진다.
- **사용법**: "이 API 명세로 목업 페이지 만들어줘" → 바로 실행되는 프로토타입,
  반복 수정, 공유.
- **필요해진 역량 — 산출물 기준으로 요구 정의**: "설명해줘"가 아니라 "이런 산출물을
  만들어줘"로 말하고, 결과를 보고 구체적으로 피드백하며 반복하는 능력.
- 출처: [Claude 3.5 Sonnet](https://www.anthropic.com/news/claude-3-5-sonnet)

### 6. 기억이 생기다 — Projects (2024.06)

- **한계**: 새 대화마다 팀 컨벤션, 프로젝트 배경, 자료를 다시 붙여넣어야 했다.
- **기능**: Projects(06.25) — 지식 문서와 커스텀 지침을 프로젝트에 담아두면
  그 안의 모든 대화가 이를 공유. (이후 2025년에는 대화 간 자동 기억(Memory)으로 확장.)
- **사용법**: "우리 팀 API 설계 가이드" 프로젝트를 만들어 규칙 문서를 넣어두고,
  리뷰·질문을 그 안에서 진행.
- **지시의 계보에서**: 시스템 프롬프트(개발자의 API 기능)가 일반 사용자의 기능이 된
  지점 — 커스텀 지침은 시스템 프롬프트의 UI 버전이다.
- **필요해진 역량 — 지식의 문서화·구조화**: 머릿속과 대화방에 흩어진 팀의 암묵지를
  재사용 가능한 문서로 만드는 능력. 문서화 잘하는 팀이 AI도 잘 쓰는 팀이 되는 지점.
- 출처: [Projects](https://www.anthropic.com/news/projects),
  [Memory](https://www.anthropic.com/news/memory)

### 7. 스스로 움직이는 실험 — Computer use (2024.10)

- **한계**: 도구가 있어도 "무엇을 할지"는 여전히 사람이 매 단계 지시해야 했다.
- **기능**: Computer use 베타(10.22) — 모델이 화면을 보고 커서를 움직여
  사람처럼 컴퓨터를 조작. 같은 주간에 분석 도구(JS 실행, 10.24)도 공개.
- **의미**: 성숙한 제품이라기보다 "모델이 스스로 루프를 도는" 에이전트 방향을
  보여준 실험. 발표에서는 '에이전트 예고편'으로 소개.
- **필요해진 역량 — 위임 범위 판단**: 맡길 일과 직접 할 일을 구분하는 감각.
  "감독자" 역할의 시작점.
- 출처: [3.5 models and computer use](https://www.anthropic.com/news/3-5-models-and-computer-use),
  [Analysis tool](https://www.anthropic.com/news/analysis-tool)

### 8. 연결의 표준 — MCP (2024.11)

- **한계**: 모델에 사내 DB, 사내 위키, 각종 SaaS를 연결하려면 서비스마다
  제각각의 통합을 만들어야 했다.
- **기능**: Model Context Protocol 오픈소스 공개 — 도구·데이터 연결의 공개 표준.
  업계 전반이 채택했고 이후 재단에 기증(2025.12).
- **사용법**: MCP 서버 하나만 만들면 Claude.ai, Claude Code 등 어떤 MCP
  클라이언트에서도 사내 도구를 쓸 수 있다. (발표에서는 개념 + 사내 활용 그림 정도)
- **필요해진 역량 — 통합 설계와 접근 경계 설정**: 사내 시스템 중 무엇을 어떤
  인터페이스로 열지, 어디까지 접근을 허용할지(보안 경계) 설계하는 안목.
- 출처: [Model Context Protocol](https://www.anthropic.com/news/model-context-protocol)

### 9. 수렴 — 추론하는 에이전트, Claude Code의 등장 (2025.02~05)

- **한계**: 복잡한 다단계 작업은 ① 더 깊은 추론과 ② 도구를 쓰며 스스로
  루프를 도는 실행력이 모두 필요했다.
- **기능**:
  - Claude 3.7 Sonnet(2025.02.24) — 첫 하이브리드 추론 모델(extended thinking)
  - **Claude Code 리서치 프리뷰(같은 날)** — 터미널에서 코드베이스를 읽고,
    파일을 수정하고, 테스트를 돌리고, 커밋하는 에이전틱 코딩 도구
  - Claude 4(Opus 4/Sonnet 4)와 함께 **정식 출시**(2025.05.22)
- **핵심 메시지**: Claude Code는 새로 발명된 것이 아니라, 지금까지의 조각들이
  개발 워크플로우에 맞게 조립된 것이다 —
  **긴 컨텍스트**(코드베이스) + **도구 사용**(파일·셸·git) + **MCP**(사내 연결) +
  **추론**(계획 수립) + **Projects의 사상**(CLAUDE.md).
- **필요해진 역량 — 작업 정의(스코핑)와 검증**: 완료 기준이 분명한 단위로 일을
  자르는 능력, 그리고 결과를 리뷰·테스트로 검증하는 능력. 코드를 "쓰는" 시간은
  줄지만 코드를 "읽고 판단하는" 능력의 가치는 오히려 커진다.
- 출처: [Claude 3.7 Sonnet](https://www.anthropic.com/news/claude-3-7-sonnet),
  [Claude 4](https://www.anthropic.com/news/claude-4)

### 10. 에이전트의 성숙 — 제어, 분업, 패키징 (2025.06~)

- **한계**: 에이전트를 팀에서 쓰려면 동작을 규칙에 맞게 제어하고, 큰 작업을
  나눠 맡기고, 반복 절차를 재사용할 방법이 필요했다.
- **기능** (Claude Code changelog 및 공식 발표 기준):
  - 훅(2025.06): 도구 실행 전후에 팀의 스크립트를 강제 실행
  - 커스텀 서브에이전트(2025.07): 작업을 전문화된 하위 에이전트에 위임
  - Claude Code 2.0 + **Claude Agent SDK**(2025.09.29): 체크포인트, VS Code 확장,
    그리고 Claude Code의 하네스를 라이브러리로 — 우리만의 에이전트 제작 가능
  - **Agent Skills**(2025.10.16): 전문 절차·지식을 폴더로 패키징해 필요할 때 로드
    (이후 오픈 표준화)
  - Claude Code on the web(2025.10.20): 브라우저·모바일에서 클라우드 실행
- **사용법**: 발표 Part 2의 "팀에서 잘 쓰기" 절이 이 단계에 해당 —
  CLAUDE.md, permissions, 훅, 스킬, MCP 설정.
- **필요해진 역량 — 환경 설계**: 에이전트가 일 잘하는 환경(CLAUDE.md, 권한, 훅,
  스킬)을 만드는 능력. 신입 온보딩 문서를 잘 쓰는 것과 같은 역량 — 팀의 규칙과
  절차를 명시적으로 만드는 팀이 에이전트 효과를 극대화한다.
- 출처: [Claude Sonnet 4.5](https://www.anthropic.com/news/claude-sonnet-4-5),
  [Agent Skills](https://www.anthropic.com/news/skills),
  [Claude Code on the web](https://www.anthropic.com/news/claude-code-on-the-web),

## 지시의 계보 — 시스템 프롬프트에서 스킬까지

주 내러티브(행동 능력의 확장)와 나란히 가는 부 축: **"반복하는 지시·맥락을
어떻게 재사용 가능하게 만들 것인가"**의 진화. 발표에서는 #6에서 복선을 깔고
Part 2 #20에서 이 표를 도식으로 회수한다.

| 시기 | 방식 | 무엇이 달라졌나 |
|------|------|----------------|
| 2023 초기 | 매 대화 프롬프트에 직접 쓰기 | 역할·규칙·맥락을 매번 반복 입력 |
| 2023.11 | **시스템 프롬프트** (Claude 2.1) | 지시를 대화에서 분리해 고정 (개발자용 API 기능) |
| 2024.06 | **Projects** 커스텀 지침 + 지식 | 일반 사용자도 지시·지식을 담아 재사용 |
| 2025 | **CLAUDE.md** (Claude Code) | 지시가 레포에 들어가 버전 관리되는 팀 자산이 됨 |
| 2025.10 | **Agent Skills** | 절차·지식을 폴더로 패키징, 필요할 때만 로드, 오픈 표준 |

핵심 통찰 두 가지:

1. **정적 로딩에서 동적 로딩으로.** 컨텍스트 창은 유한한 자원이다. 그래서 진화
   방향은 "항상 다 넣기"(시스템 프롬프트)에서 "필요할 때 필요한 것만
   로드하기"(스킬)로 갔다 — 개발자에게 익숙한 로딩 전략의 문제와 같다.
2. **개인 → 팀 → 생태계.** 프롬프트(개인) → Projects(팀 공유) →
   CLAUDE.md(버전 관리) → Skills(오픈 표준 패키지)로, 지시의 소유와 유통
   단위가 커져 왔다.

주의: 스킬은 이 한 줄기에서만 나온 것은 아니다(슬래시 커맨드·도구 사용의 사상도
섞여 있다). 발표에서는 "이 흐름의 연장선"으로 표현하고 "스킬 = 시스템 프롬프트의
후손" 같은 단정은 피한다.

## 권한의 계보 — 안전 경계의 진화 (permissions)

Introduction ②의 "일을 시키는 법" 줄에 추가된 **permissions** 축의 근거 자료.
"후배에게 권한을 얼마나, 어떻게 주고 제한할 것인가"가 어떻게 기능이 되어 왔는가.
(출처: code.claude.com/docs의 permissions·permission-modes·sandboxing·hooks 문서,
computer use 공식 가이드. 2026-08-31 조사. 세부 버전·월은 일부 근사 — 발표 인용 시
"~부터", "~무렵" 수준으로 표현할 것.)

| 시기 | 방식 | 무엇이 달라졌나 |
|------|------|----------------|
| 2023 (채팅) | 권한이 없음 | 모델은 읽고 답할 뿐 — 실행은 전부 사람 손. 경계 문제 자체가 없었다 |
| 2024.05 (Tool use) | 개발자가 실행을 소유 | API 도구 사용은 설계상 **클라이언트 실행** — 모델은 "이 도구를 이렇게 호출해달라"는 요청만 반환, 실행·검증·로깅은 개발자 몫. human-in-the-loop이 구조적 기본값 |
| 2024.10 (Computer use 베타) | 격리 권고 | Anthropic이 VM·컨테이너 격리, 최소 권한 실행을 공식 권고 — 프롬프트 인젝션 등 위험에 대한 첫 공식 안전 지침 |
| 2025.02~ (Claude Code) | **permissions 체계 내장** | 도구 호출마다 승인 프롬프트가 기본. `settings.json`의 allow/deny/ask 규칙으로 패턴 단위 제어(`Bash(npm run *)` 등), 권한 모드(default/acceptEdits/plan/bypassPermissions 등), 설정 계층(사용자 → 프로젝트 → 로컬 → 관리형) |
| 2025.06 (훅) | 결정적 정책 집행 | PreToolUse 훅이 도구 실행 전에 스크립트로 검사·차단 — LLM의 판단이 아니라 **결정적 코드**로 팀 규칙을 강제. deny 규칙은 훅으로도 우회 불가 |
| 2025~ (샌드박스) | 경계 자체를 격리로 | Bash 샌드박스: 파일시스템(읽기/쓰기 허용 목록) + 네트워크(도메인 허용 목록) 이중 격리 (macOS Seatbelt, Linux bubblewrap). Claude Code on the web(2025.10)은 세션마다 격리된 VM + 네트워크 정책 |
| 팀/조직 | 관리형 정책 | managed settings로 조직 전체에 규칙 강제 — bypassPermissions 비활성화 등. 조직의 deny는 프로젝트 설정이 뒤집을 수 없음 |

핵심 통찰 세 가지:

1. **승인에서 규칙으로, 규칙에서 구조로.** "사람이 매번 승인"(프롬프트) →
   "규칙으로 위임"(allow/deny, 훅) → "격리로 구조화"(샌드박스) — 신뢰가 아니라
   **구조**로 안전을 확보하는 방향으로 진화했다.
2. **권한 도구는 능력과 동행한다.** 행동 능력이 커질수록 경계 도구도 정교해졌다.
   권한 체계는 에이전트를 막는 것이 아니라, 안심하고 더 많이 맡기게 하는 장치다.
3. **후배 은유로**: 첫날엔 견학만(채팅) → 감독하에 실습(승인 프롬프트) →
   업무 범위 명시(allow/deny 규칙) → 전용 작업 공간 제공(샌드박스).
   신입에게 권한을 열어주는 순서와 정확히 같다.

발표 회수 지점: Part 1 #15(안전 수칙), Part 2 팀 설정 ②(permissions·훅 상세).

## 역량의 이동 — 시대별로 사람에게 요구된 것

기능의 발전은 곧 사람 역할의 이동이었다. 발표에서 각 단계 말미에 한 줄씩 짚고,
마무리에서 아래 표로 종합한다.

| 시대 | 사람의 역할 | 핵심 역량 |
|------|-------------|-----------|
| 채팅 시대 (2023) | 질문자 | **잘 묻기** — 맥락·의도·형식을 언어로 정리 (프롬프트 작성) |
| 기능 확장 시대 (2024) | 준비자·편집자 | **잘 준비하기** — 컨텍스트 큐레이션, 입력 형태 선택, 산출물 기준의 요구 정의, 팀 지식의 문서화 |
| 에이전트 시대 (2025~) | 위임자·감독자 | **잘 맡기고 잘 검증하기** — 작업 스코핑, 환경 설계(CLAUDE.md·권한·스킬), 리뷰·테스트로 검증, 오케스트레이션 |

세 가지 강조점:

1. **역량은 대체되지 않고 누적된다.** 에이전트 시대에도 잘 묻기(프롬프트)와
   잘 준비하기(컨텍스트)는 그대로 필요하다 — 그 위에 위임·검증이 얹힐 뿐.
2. **"쓰는 능력"에서 "읽고 판단하는 능력"으로.** 코드를 직접 작성하는 시간은
   줄지만, 결과물을 읽고 품질을 판단하는 엔지니어링 기본기의 가치는 커진다.
3. **개인 역량에서 팀 역량으로.** 프롬프트는 개인기지만 CLAUDE.md·스킬·MCP는
   팀의 자산이다. 문서화와 절차의 명시화가 잘 된 팀이 에이전트 효과를 극대화한다.
