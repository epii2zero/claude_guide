**터미널 하나로 5분 안에 시작할 수 있다**

```bash
npm install -g @anthropic-ai/claude-code
cd our-project && claude        # 로그인 후 바로 대화 시작
```

| 진입점 | 특징 |
|--------|------|
| **CLI (터미널)** | 원형 — 최신 기능을 제일 먼저 지원 |
| **VS Code · JetBrains 확장** | 익숙한 IDE 안에서 — diff 보기 편리 |
| **Claude desktop** | 편리한 GUI, 코드와 채팅 둘 다 — 로컬·클라우드·SSH 환경 + 원격 컨트롤 |
| **claude.ai/code (웹)** | 브라우저·모바일 일부 — 클라우드 환경 전용, 자동 메모리 미지원 |

# 팀 설정 ① CLAUDE.md — 에이전트에게 주는 온보딩 문서

**문제: Projects 지침은 claude.ai 계정 안에 있었다 — 코드 곁에, 팀 모두에게, 버전 관리되게 둘 수는 없을까**

```markdown
# CLAUDE.md (레포 루트 — 세션 시작 시 자동 로드)
## 빌드·테스트
- pnpm test 로 테스트, pnpm lint 로 린트
## 컨벤션
- API 응답은 반드시 공용 에러 포맷 사용 (src/lib/errors.ts)
- 커밋 메시지는 conventional commits
```

- 있을 때 vs 없을 때: 같은 요청에도 팀 규칙을 아는 응답 / 모르는 응답 (#18 데모 4번)
- **부 축 세 번째 정거장**: 지시가 **버전 관리되는 팀 자산**이 된 지점 — 리뷰·PR로 함께 다듬는다

**역량 ⑨ 환경 설계** — 후배가 일 잘하게 책상을 차려주는 일

# 팀 설정 ② 권한과 훅 — 맡기되, 고삐는 우리 손에

**문제: 파일을 고치고 명령을 실행하는 후배 — 어디까지 허용할지 누가 정하나 (Introduction ②의 "permissions")**

```
권한(permissions)  — 도구 호출마다 허용/확인/차단
  allow: 테스트 실행, 파일 읽기      ask: git push      deny: rm, 배포 명령
  설정 계층: 조직(강제) > 프로젝트(.claude/settings.json) > 개인

훅(hooks, 2025.06) — 도구 실행 전후에 끼어드는 스크립트 (결정적 실행)
  예: 파일 수정 후 자동 포맷터 실행 / 위험 명령 사전 차단
```

- 권한은 **모델에게 부탁하는 게 아니라 시스템이 강제** — 지침("하지 마")과 결정적 차이
- 데모에서 본 그 확인 프롬프트가 바로 이 권한 시스템

# Skills — 반복 지시의 최종 진화

**문제: CLAUDE.md도 결국 "항상 전부 로드" — 지시가 쌓일수록 컨텍스트 창을 잡아먹는다**

```
skills/deploy-check/SKILL.md
  ---
  name: deploy-check          ← 이름·설명(메타데이터)만 상시 로드
  description: 배포 전 점검 절차. 배포·릴리즈 요청 시 사용.
  ---
  본문(절차 상세)             ← 관련 작업일 때만 로드
  참조 파일·스크립트          ← 필요해진 순간에만 로드
```

**지시의 계보, 완성**: 매 대화 반복 입력 → 시스템 프롬프트(2023.11) → Projects(2024.06)
→ CLAUDE.md(2025) → **Agent Skills(2025.10, 오픈 표준)**

- 전환의 핵심: **"항상 다 넣기(정적)" → "필요할 때 필요한 것만(동적)"** — 컨텍스트 창은 유한한 자원
- Claude 앱·Claude Code·API 공통 — 한 번 만든 스킬을 어디서나
- **여러분이 매번 붙여넣는 그 지시가 스킬이 될 후보다**
