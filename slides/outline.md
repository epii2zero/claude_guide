# 슬라이드 구성안 (초안)

> **작업 방식**: 실제 슬라이드를 만들기 전에 이 MD에서 장별 구성을 먼저 확정한다.
> 각 슬라이드는 **제목 / 핵심 메시지(그 장에서 청중이 가져가야 할 한 문장) /
> 내용 요소 / 발표 포인트**로 정의한다. 구성이 확정되면 이 문서를 기준으로
> 실제 슬라이드를 제작한다.
>
> 근거 자료: `PLAN.md`(구성·시간 배분), `docs/00-evolution.md`(타임라인·역량, 출처 포함)

- 총 분량: **2시간(120분)** — 오프닝 5 / Part 1 40 / 휴식 10 / Part 2 50 / 마무리·Q&A 15
- 슬라이드 수: 25장 내외 유지 (장수를 늘리기보다 장당 시간을 늘려 미니 시연·데모에 사용)
- 표기: `[도식]` 그림 필요, `[예시]` 실제 예시 화면/코드 필요, `[데모]` 라이브 데모 전환점,
  `[미니시연]` Claude.ai 실제 화면으로 짧게 시연 (스크린샷 대체)

## Part 1. 채팅에서 에이전트까지 (40분, #4~15)

> 2시간 확대로 이 파트의 예시 다수를 스크린샷 대신 실제 화면 미니 시연으로 진행한다.

### #4. 전체 타임라인 조망
- **핵심 메시지**: 모든 기능은 "더 많은 컨텍스트, 더 많은 행동 능력" 한 방향의 진화였다
- 내용: 2023~2026 타임라인 한 장 `[도식]` (00-evolution.md의 요약 도식 기반)
- 발표 포인트: 여기서는 조망만, 각 단계는 이어지는 슬라이드에서

### #5. 출발점 — 단순 채팅 (2023)
- **핵심 메시지**: 유용했지만 복붙 워크플로우, 갇힌 지식, 환각이라는 한계가 뚜렷했다
- 내용: 첫 Claude(2023.03), claude.ai 공개(2023.07) / 질문-답변 모델의 가치와 3가지 한계
- 발표 포인트: "이 한계 하나하나가 이후 기능이 된다"로 다음 장들 예고

### #6. 기본기 — 잘 묻기 (프롬프트)
- **핵심 메시지**: 맥락·의도·형식을 정리해 묻는 능력은 지금도 모든 것의 바탕이다
- 내용: 안 좋은 질문 vs 좋은 질문 비교 `[미니시연]` (에러 디버깅 요청 사례 권장 — 두 질문을 실제로 던져 응답 차이 보여주기) / 맥락 제공·역할·출력 형식·단계적 요청
- 발표 포인트: **역량 ①: 잘 묻기** — 시대별 역량 축의 첫 항목임을 명시

### #7. 컨텍스트의 확장 (2023: 100K→200K)
- **핵심 메시지**: 자료를 쪼개 넣던 시대에서 통째로 넣는 시대로
- 내용: 100K(2023.05)→200K(2023.11)→이후 1M / 사용법: 로그·문서·코드 통째로 첨부
- 발표 포인트: **역량 ②: 컨텍스트 큐레이션** — "많이"가 아니라 "잘" 넣기

### #8. 눈이 생기다 — 비전 (2024.03)
- **핵심 메시지**: 말로 옮겨 적지 말고 그냥 보여줘라
- 내용: Claude 3 패밀리 + 이미지 입력 / 에러 스크린샷·다이어그램·UI 시안 `[미니시연]`
- 발표 포인트: **역량 ③: 입력 형태 선택** — 설명 10줄보다 스크린샷 1장

### #9. 손이 생기다 — Tool use (2024.05)
- **핵심 메시지**: 모델이 학습 지식 밖의 세계와 상호작용하기 시작했다 — 에이전트로 가는 첫 단추
- 내용: Tool use 정식 출시 / 웹 검색(2025.03)·분석 도구 등으로 확장 / 동작 원리 간단 도식 `[도식]`
- 발표 포인트: **역량 ④: 능력 범위 파악** / "첫 단추"라는 표현으로 수렴 지점 복선

### #10. 산출물이 생기다 — Artifacts (2024.06)
- **핵심 메시지**: 대화가 아니라 작업물을 받는다
- 내용: 코드·문서·동작하는 프로토타입 `[미니시연]` (실행되는 HTML 목업을 실제로 생성)
- 발표 포인트: **역량 ⑤: 산출물 기준으로 요구 정의** — "설명해줘"가 아니라 "만들어줘"

### #11. 기억이 생기다 — Projects (2024.06)
- **핵심 메시지**: 매번 다시 붙여넣지 말고 담아두고 재사용하라
- 내용: 지식 문서 + 커스텀 지침 / 팀 활용 예시 ("팀 API 설계 가이드" 프로젝트) `[미니시연]` / 이후 Memory로 확장
- 발표 포인트: **역량 ⑥: 지식의 문서화** — 뒤의 CLAUDE.md와 연결되는 복선

### #12. 스스로 움직이는 실험 — Computer use (2024.10)
- **핵심 메시지**: "매 단계 지시"에서 "맡기고 지켜보기"로 — 에이전트 예고편
- 내용: 화면을 보고 커서를 움직이는 베타 데모 이미지 1장 / 성숙한 제품이 아닌 방향 제시용 실험임을 명시
- 발표 포인트: **역량 ⑦: 위임 범위 판단** — 감독자 역할의 시작

### #13. 연결의 표준 — MCP (2024.11)
- **핵심 메시지**: 서비스마다 제각각이던 도구 연결이 하나의 공개 표준이 됐다
- 내용: MCP 개념 도식 `[도식]` (하나의 MCP 서버 ↔ 여러 클라이언트) / 사내 도구 연결 그림
- 발표 포인트: **역량 ⑧: 통합 설계와 접근 경계 설정** / 개념 소개 수준, 상세는 Part 2

### #14. 수렴 — 왜 에이전트인가 (2025.02~)
- **핵심 메시지**: 지금까지의 모든 조각이 "스스로 루프를 도는 모델"로 조립된다
- 내용: 긴 컨텍스트 + 비전 + 도구 + 산출물 + 지식 + MCP + 추론(extended thinking)이 한데 모이는 조립 도식 `[도식]` / Claude Code 등장(2025.02) 예고
- 발표 포인트: Part 1의 클라이맥스. 이 장이 발표 전체의 논리적 중심

### #15. 한계와 주의점
- **핵심 메시지**: 능력이 커질수록 검증 습관과 보안 경계가 중요해진다
- 내용: 환각 → 검증 습관 / 사내 보안 정책 (코드·데이터 반출 기준) — 사내 정책 확인 후 확정
