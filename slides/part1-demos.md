# Part 1 미니 시연 스크립트

> 시연 5개의 프롬프트 원문·준비물·타이밍·실패 대비책.
> 리허설 시 이 문서를 그대로 따라 하면 재현된다.
> 준비물 실물은 `demo/part1/` 폴더에 만들어 둘 것 (아래 각 시연의 "준비물" 참고).

공통 원칙
- 시연은 모두 claude.ai 웹에서, 발표 전용 계정/프로젝트로 진행 (개인 대화 노출 방지)
- 각 시연마다 **사전에 같은 프롬프트로 1회 실행해본 결과 스크린샷**을 백업 슬라이드로 준비
- 응답 대기 시간(수 초~수십 초)에 말할 멘트를 각 시연에 명시

---

## 시연 1 — 나쁜 질문 vs 좋은 질문 (#6, 3분)

**목적**: 답의 품질을 가르는 건 모델이 아니라 입력의 질임을 체감시키기.

**준비물** (`demo/part1/`)
- `orders_api.py` — 페이지네이션 버그가 있는 주문 목록 API 함수 (30줄 내외)
- `error.log` — 위 코드 실행 시의 트레이스백

예시 자료 초안 (실물 파일 생성 시 이 내용 기반):

```python
# orders_api.py (발췌)
def list_orders(page: int, size: int = 20):
    offset = page * size          # 버그: page가 1부터 오는데 0부터로 계산
    rows = db.query(
        "SELECT * FROM orders ORDER BY created_at DESC "
        f"LIMIT {size} OFFSET {offset}"
    )
    return [Order.from_row(r) for r in rows]
```

```
# error.log (발췌) — 실제로는 IndexError가 아니라 "1페이지와 2페이지에
# 같은 주문이 보인다"는 동작 버그 리포트로 구성해도 좋음 (논의 후 확정)
```

**진행**

1. 나쁜 질문 먼저 (새 대화):
   ```
   코드가 안 돌아가요. 고쳐주세요.
   ```
   → 일반론적인 답이 오는 것을 확인. "당연히 이렇게밖에 못 답합니다."
2. 좋은 질문 (새 대화, 파일 2개 첨부):
   ```
   주문 목록 API에 페이지네이션을 추가하는 중입니다. (orders_api.py, error.log 첨부)
   증상: 1페이지와 2페이지에 같은 주문이 중복돼 보입니다.
   제약: DB 스키마는 변경할 수 없습니다.
   요청: 원인 후보 2개와 각각의 수정안을 diff 형태로 제시해주세요.
   ```
   → 구체적 원인(오프셋 계산)과 diff가 오는 것을 확인.
3. 마무리 멘트: "모델은 같습니다. 달라진 건 **맥락 + 자료 + 제약 + 출력 형태**뿐입니다."

**대기 중 멘트**: "지금 제가 한 일은 '동료에게 물어볼 때의 예의'와 같습니다. 재현 조건과 제약을 주는 것."

**실패 대비**: 두 응답의 사전 캡처 2장.

## 시연 2 — 긴 컨텍스트: 로그 통째로 (#7, 1분)

**목적**: "쪼개지 말고 통째로"를 눈으로 확인.

**준비물** (`demo/part1/`)
- `app_full.log` — 수천 줄짜리 로그 (중간 1곳에 커넥션 풀 고갈 등 실제 원인이 심어진 것)

**진행** (시연 1의 좋은 질문 대화에서 이어가면 자연스러움)

```
오늘 오전 장애 시점의 전체 로그입니다. (app_full.log 첨부)
장애의 근본 원인으로 보이는 지점을 찾아 시각 순서대로 설명해주세요.
```

→ 수천 줄에서 원인 라인을 짚어내는 것 확인.

**멘트**: "3년 전엔 이 로그를 잘라서 스무 번에 나눠 넣어야 했습니다."

**실패 대비**: 응답 캡처 1장.

## 시연 4 — Artifacts: 동작하는 목업 (#10, 3분)

**목적**: "대화가 아니라 산출물"을 가장 극적으로 보여주는 시연.

**준비물** (`demo/part1/`)
- `pets_api.md` — 간단한 가짜 API 명세 (아래 초안)

```markdown
# Pets API (v1)
GET  /pets?type={dog|cat}     → [{id, name, type, age}]
POST /pets                    → {id}  (body: {name, type, age})
GET  /pets/{id}               → {id, name, type, age, adopted}
```

**진행** (새 대화, 명세 첨부)

1. ```
   이 API 명세로 관리자용 목업 페이지를 만들어주세요.
   목록 조회 + 등록 폼, 데이터는 하드코딩 샘플로. 단일 HTML로요.
   ```
   → Artifact 창에 동작하는 페이지가 뜨는 것 확인, 버튼 클릭 시연.
2. 수정 요청 1회:
   ```
   목록에 type 필터 탭(강아지/고양이)을 추가해주세요.
   ```
   → 즉시 반영 확인.
3. 마무리 멘트: "기획 리뷰 전에 이걸 10분 만에 만들어 가면 회의가 달라집니다."

**실패 대비**: 완성 목업의 화면 녹화(30초) 또는 캡처 2장.

## 시연 5 — Projects: 지침의 힘 (#11, 2분)

**목적**: 담아둔 지침이 모든 대화에 자동 반영됨을 확인. CLAUDE.md 복선.

**준비물** (claude.ai에 사전 구성)
- 프로젝트 "팀 API 설계 가이드" — 커스텀 지침 예:
  ```
  우리 팀 API 컨벤션:
  - 에러 응답은 항상 {code, message, traceId} 형태
  - 페이지네이션은 cursor 방식만 사용 (offset 금지)
  - 모든 응답 필드는 snake_case
  답변 시 이 컨벤션을 반드시 반영할 것.
  ```

**진행**

1. 프로젝트 **밖** 일반 대화에서:
   ```
   주문 목록 조회 API의 응답 스키마를 설계해주세요.
   ```
   → 일반적인 설계(offset 페이지네이션 등)가 옴.
2. 프로젝트 **안**에서 같은 질문:
   → cursor 방식 + snake_case + 에러 형태까지 팀 컨벤션이 반영된 설계가 옴.
3. 마무리 멘트: "같은 질문, 다른 답. 차이는 담아둔 지침뿐입니다.
   이 지침이 코드 레포로 들어간 것이 잠시 후 볼 CLAUDE.md입니다."

**실패 대비**: 두 응답의 사전 캡처 2장.
